# SITS Salud · Royal

Rediseño integral de presentación sobre el backend operativo. Identidad original preservada; tema azul rey, navegación institucional destacada, catálogo con portada y tarjetas, formulario y estados mejorados, panel de trabajo por módulo, gestión de categorías y trámites, constructor en secciones, directorio de personal con búsqueda y edición, y controles de accesibilidad. Se usan las acciones de backend existentes. No se modifica configuración Firebase ni el flujo de almacenamiento/correo, no se habilita información clínica real. El alta de cuentas nuevas requiere una invitación/alta de identidad autorizada; el backend anterior permite asignar roles a UID previamente habilitados. Se conserva el rol supervisor protegido y no se crean credenciales desde el cliente.

## Invitaciones de personal
La nueva versión de Apps Script añade invitaciones privadas por correo Google institucional, con vencimiento a siete días, revocación, rol operador/administrador funcional, historial de alta y activación única. Se comprueba la identidad verificada y se escriben las altas Firestore con precondiciones atómicas. No se reactiva una cuenta deshabilitada, no se crea un supervisor y no se solicita contraseña. La pantalla detecta esta capacidad mediante staffList.invitations; en el backend previo conserva la gestión por UID. La nueva funcionalidad requiere desplegar el bundle generado por scripts/prepare-spark.mjs en la implementación existente por una sesión autorizada de Salud. No se necesita modificar Firebase, índices adicionales ni propiedades. No se han ejecutado las nuevas invitaciones en producción; las pruebas de CI son simuladas. El despliegue Pages no actualiza Apps Script automáticamente.
