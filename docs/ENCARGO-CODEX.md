# Instrucción de ejecución para Codex
Trabaja directamente en adminterritorial-bit/TRAMITE-DE-DISCAPACIDAD. Lee completo docs/PLAN-MAESTRO-SALUD.md antes de modificar código y úsalo como contrato de aceptación. Implementa SITS Salud, plataforma integral y configurable de trámites de la Secretaría de Salud. Reutiliza el frontend, Firebase Spark, Drive y Apps Script que ya funcionan. No migres de proveedor, no actives facturación, no hagas otra maqueta, no solicites al usuario configuraciones ya hechas ni le entregues una lista de pendientes solucionables por ti. Inspecciona el último main, crea una rama de integración, implementa todos los módulos, prueba y corrige errores, prepara un solo backend desplegable, CI y GitHub Pages, abre PR y presenta evidencia real. Mantén modo sintético y privacidad de datos de salud hasta autorización institucional. Diferencia lo probado en CI de lo probado en infraestructura real. No publiques datos reales ni declares éxito sin confirmarlo. Si el acceso a Apps Script no está autorizado, resuelve todo lo demás y entrega una única acción manual consolidada. El objetivo es una aplicación utilizable en todas sus funciones, no fragmentos de código. No te detengas tras elaborar un plan.

Además, lee y ejecuta obligatoriamente docs/IDENTIDAD-UX-Y-CUMPLIMIENTO.md. Incorpora ambos originales del paquete SITS-Salud-logos-originales.zip en public/assets/brand/ respetando el Manual de Identidad Visual, con revisión de marca territorial. Construye animaciones ligeras y accesibles, pantallas de carga funcionales, sistema de avisos administrable y políticas versionadas con evidencia de aceptación/consentimiento según base jurídica. Implementa la matriz de cumplimiento TIC, accesibilidad, protección de datos, seguridad y archivo. No te limites a redactar documentos: integra y prueba sus controles. No elimines restricciones del piloto ni publiques datos reales hasta aprobación institucional.
